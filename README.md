# bili-helper · B 站增强助手

网页版哔哩哔哩（bilibili.com）的浏览器增强扩展。在不多打扰你的前提下，把 B 站变得更清爽、更快、更顺手：过滤不想看的视频、净化页面广告、优化播放器体验，并内置一套 **AI 助手**，帮你识别并跳过恰饭广告、总结视频、就视频内容提问。

> **本仓库的源码范围**：目前只重建了 **AI 助手**，能力面就三件事——去广告、总结、提问（`modules/`、`entrypoints/`、`server/`，构建产物 `.output/chrome-mv3` 的 content script 仅作用于视频页）。
> 过滤 / 净化 / 布局 / 增强，以及旧版里的 **ASR 音频转字幕、字幕润色**等能力，都仍留在**重建前的旧打包产物**里（仓库根目录，`.gitignore` 标注为「本地逆向参考，不进源码仓库」），**尚未纳入本仓库源码**，也不在 `.output/chrome-mv3` 里——下文相关章节开头都标了出处。

## 🤖 AI 助手

打开任意视频，右侧会注入一个 AI 面板，含「总结 / 提问」两个标签页。扩展图标弹窗里有两条页内快开关（**AI 去广告**、**总结面板**），只作用于当前页面，用来临时压掉不想看的东西，不改全局设置。

### 自动跳过恰饭广告

自动识别视频里「恰饭 / 带货」片段（通常 3 秒前开始提示）：

- 播放器顶部弹出提示条，显示商品名、累计已节省时长；
- **3 秒倒计时后自动跳过**该片段继续播放——什么都不点也会跳；
- 也可以点「马上跳」立刻跳过，或「这段想看」留在原地；
- 识别出的广告片段会在进度条上打标记（标记锚在**进度条本体**上高频跟随，播放器控制层淡出/收起时一起隐藏，不会悬在半空），并在「总结」的分段列表里标出「广告」；
- **只有置信度足够高的片段才自动跳过**：端点故障时检索兜底出的低置信片段只打标记、不接管播放器，避免把正片当广告跳掉。

### 视频总结

基于字幕生成 Markdown 总结正文，下方附一份「视频分段」时间线：每段显示起止时间和标题，**点击即可跳到对应时间点**，广告段带专属标签。

### AI 提问

围绕当前视频的 AI 对话：会预置推荐问题（内容是什么、精华片段、重要结论、怎么安利给朋友），也支持自由提问，全程基于视频的字幕上下文回答，流式输出并在相关处标注字幕时间点、点击即可跳播。

### AI 去广告是怎么做的

去广告是全项目技术含量最高的一环——**核心问题不是"有没有广告"，而是怎么用最少的 token、最快的速度，把字幕+弹幕里多出来的那段"恰饭"精准定位出来**。如果直接把整段字幕和几千条弹幕一股脑丢给大模型，既慢又费钱。

所以采用 **混合检索 RAG + LLM 精确定界** 两段式：

```text
视频字幕（按 30 秒窗口切块）──┬─► ① 词表 / BM25：字面精确匹配 ──┐
（无字幕则用弹幕切块）        ├─► ② 向量语义检索（/embeddings）─┼─► RRF 融合排序 ─► 候选广告窗口
                              └─► ③ 弹幕信号召回：观众反应 ─────┘
                                                                        │
                                                                        ▼
                                                      LLM 精确定界（只喂候选窗口 ± 上下文）
                                                      → {start, end, 商品名, 置信度}
```

四个关键点：

1. **三路混合检索**：词表/BM25 抓「字面精确命中」（品牌名、"赞助""团购"），向量抓「语义变体」（黑话、委婉说法、新梗），弹幕信号抓「观众反应」（同一 30 秒窗口 ≥2 条弹幕含广告词或语料词，命中「前方高能广告」这类元词额外加权）——三条路互补后用 RRF（倒数排名融合）合并排序。单一方式都覆盖不了广告话术的多样性；弹幕那路还让**没有字幕的视频照样能识别**（字幕为空时直接用弹幕窗口做检索底料）。

2. **父子窗口（small-to-big）**：先用小窗口（约 30 秒、单窗口文本上限 400 字）召回"疑似广告"，命中后再回取父级大窗口（±N 秒上下文）喂给 LLM，让它在足够上下文里定出精确起止时间——而不是让模型自己漫无边际地找。

3. **LLM 精确定界**：模型只处理候选窗口（最多 10 个），输出结构化的广告起止时间、商品名和置信度；结果驱动进度条标记和自动跳过。

4. **降级链与护栏**：自定义端点不支持 `/embeddings` 时自动退化为纯词表检索；**对话端点未配置或不可用时自动走「极速匹配」**（纯检索定界，只需向量端点，精度略低、零对话开销）；纯检索无命中**且弹幕/评论有广告线索**时再兜底直连 LLM 全量分析——没有任何线索的视频不花这笔钱。护栏两条：兜底段**合并后仍超过 120 秒的整段丢弃**（纯检索没有定界能力，刷屏词会合并出横跨大半视频的巨段），兜底置信度**封顶 0.6、低于自动跳过门槛 0.7**，所以端点挂掉时你看到的是标记而不是乱跳。

**省 token 的六道闸**（去广告是高频功能，按"每次检测几厘钱"设计）：

1. **上下文预算**：候选窗口内弹幕经「信号优先 + 无偏采样」精选到每窗 ≤40 条（信号弹幕占预算一半、其余按时间均匀采样——只喂广告弹幕会把模型带偏），字幕行每窗 ≤200 行；候选窗口 ≤10 个、顶部评论 ≤20 条。
2. **双源强一致免 LLM**：每个候选窗口都被词表命中、且 ≥3 条**不同文本**的弹幕在指认（同句刷屏不算）时，直接给 0.75 置信度成段——高于 0.7 自动跳过门槛，**零对话调用也能自动跳**。
3. **结果缓存**：按 `bvid:cid` 缓存检测结果（含「没广告」的负缓存），指纹绑定算法版本 + 端点/模型 + 生效语料哈希，改配置自动重算；LRU 200 条。重复观看/回看零 token。
4. **观看门槛**：真实看了 ≥15 秒才发起检测——秒退/划走的视频零成本（拖进度条也算在看，立即放行）。
5. **全文兜底闸门**：召回零命中且弹幕/评论没有任何广告线索时，直接空结果收尾，不走最贵的全文定界。
6. **去广告专用端点**：设置页「高级 → 去广告端点（可选 · 省 token）」可单独指定便宜模型（默认继承对话端点）——定界是约束很强的结构化任务，flash 档够用，单价比 pro 档低一个量级；总结/提问仍走对话端点。

每次检测的路径（cache / consensus / llm / fulltext / retrieval / none）、对话次数与 token 用量都回传展示：控制台完成日志带 `路径=… token=入N/出N`，设置页诊断控制台有「去广告开销」逐次列表与合计（如"最近 20 次：输入 32,100 / 输出 1,800 token，14 次零成本（70%）"）。

**字幕从哪来**：先读页面播放器状态里的字幕轨；拿不到时用登录态请求 `x/player/wbi/v2`（WBI 签名）兜底；AI 字幕 JSON 托管在 `aisubtitle.hdslb.com`，URL 自带 auth_key，因此**必须不带凭据请求**（带 `credentials` 会被 CDN 拒绝）。这条链路在控制台留了里程碑日志（字幕轨数 / 选中语言 / 解析行数），"没有标记"时先看它。

**向量缓存**：语料向量与视频窗口向量都缓存在本地，键上标注「embedding 模型 + 端点地址 + 语料内容哈希」，换模型或改语料会自动失效重算，避免不同向量空间混用。

### 广告词库：分品类 md + 用户补录

检索用的信号词库是**一层内置 + 一层用户补录**：

- **内置层** `modules/ai/rag/corpus/*.md`：按品类分文件（`scripts` 恰饭话术、`slang` 黑话新梗、`deals` 交易信号、`brands-{games,digital,beauty,food,ecommerce,app,auto,appliance,platform}` 各行业品牌词）。一行一条，`#` 开头是注释，`词|N` 覆盖默认权重；**文件名即元信息**（决定信号类别与默认权重），构建期由 `import.meta.glob` 内联打包，加词不用碰任何代码——改一行，语料哈希就变，向量缓存自动重算。
- **用户层**：设置页「广告词库」卡片，与面板里的两个就地补录入口。遇到没识别出来的广告，把关键词补录进去（选个品类、可选填来源备注），保存即生效，下次识别就会召回。补录的词存在本地（上限 500 条、单条 40 字），与内置层合并后一起参与词表匹配和向量检索；也可以一键**导出入库 patch**（格式与 `corpus/*.md` 完全一致），交给维护者审核合入内置词库、随下个版本发布。
  - **批量粘贴**：一次贴多行（每行一条），统一选品类；重复项与非法条目会被跳过并列出原因。
  - **命中统计**：每条词显示「命中 N 次」与最近命中时间，从未命中的是灰色——方便清理没用的词。
  - **面板「漏检补录」**：在「总结」页底部打开，取当前播放位置 ±30 秒的字幕切成候选信号词（已过滤常用词），勾选几条即可入库，不用自己回想原话。
  - **广告段一键「品牌词入库」**：分段列表里每个广告段旁的按钮，直接把该段识别出的商品名收进词库。

> 注意：用户层词条只在**浏览器直连识别**时参与检索。开了「我有自己的服务器」后，识别跑在服务端、用的是服务端自己的词库，这时补录的词不会生效——需要把导出的 patch 合进服务端的 `corpus/*.md`（设置页在该模式下会明确提示这一点）。

分层的理由：扩展 bundle 运行时不可写，用户提交无法直接落进 md；更重要的是未经审核的词进精确匹配词表会拉高全库误伤率（比如「花火」既是 B 站商单平台名，又是《星穹铁道》角色名），所以运行时只写用户层，入库走审核。审核规则与检查清单见 [modules/ai/rag/CORPUS.md](modules/ai/rag/CORPUS.md)。

### AI 端点接入

去广告、总结、提问全部**直连你自己配置的 OpenAI 兼容端点**，不经过任何第三方中转——API Key 只发给你指定的地址。

内容脚本（B 站页面）里的 AI 流量统一经**后台 service worker 代取**（`net-relay` 端口中继）：后台带着 `http/https` host_permissions，fetch 不受页面跨域（CORS）约束，端点不必放行 B 站源；长流式回答有保活心跳防 SW 闲置熄火。注意请求仍走**系统代理**——本地代理工具（如 Clash）需放行端点域名或配直连规则，否则会报「请求发不出去」。

设置页只问两个是非题，不要求你理解模式术语：

- **「我有自己的服务器」关**（默认）：浏览器直连你填的端点。向量端点默认继承对话端点，需要拆分时展开「高级」即可（「高级」里还有可选的**去广告专用端点**——给高频的定界任务配个便宜模型，见上文"省 token 的六道闸"）。
- **开关打开**：AI 请求统一发到你的服务器（`{serverBaseUrl}/ai/{ad-detection,summary,chat}`，填了 token 就带 `Authorization: Bearer`），检索与模型调用都在服务端做。
- **再勾上「服务器失败时回退浏览器直连」**：服务器挂了自动改用本地端点继续工作。

每个端点卡片（对话 / 向量 / 服务器）自带「测试连接」按钮：贴着字段就地探测当前表单值（改了没保存也测新值），红绿灯直接告出可用性与原因。地址带不带 `/v1` 都可以——对话与模型列表请求会自动按两种拼法尝试（`…/messages` 与 `…/v1/messages` 等），Anthropic 协议的 Key 也同时兼容 `x-api-key` 与 `Bearer` 两种鉴权头。端点不提供模型列表接口时（例如火山方舟的 coding 网关），会提示**手动填写模型名**——模型下拉框本身支持直接输入。

### 诊断与排障

两层诊断，出问题不用猜：

1. **诊断控制台**（设置页底部，终端样式）：失败记录环形 20 条、最新在前，每条含时间、功能（总结 / 提问 / 去广告 / 连通测试 / 模型列表）、错误类型、文案、端点与模型名，以及**模型原始回复的摘录**（解析失败时最有用）；下方「去广告开销」逐次列出检测路径、token 用量与耗时，并给出合计与零成本占比。点「打开控制台」展开，展开期间每 5 秒自动刷新，点终端本体也可手动刷新；只记失败与用量、不含任何密钥。连通测试与模型列表探测失败也会落进这里。
2. **页面控制台** `[bili-helper]` 里程碑日志：字幕链路（兜底接口 code / 登录 mid / 字幕轨数 → 选中语言 / 解析行数）、去广告（`检测开始 bvid=… 字幕=N行 弹幕=N条` → `检测完成 source=… 广告段=N 可自动跳过=N 耗时=Ns 路径=llm 对话=1次 token=入3210/出180 → 区间(商品名,置信度)`，缓存命中是 `检测缓存命中 …（0 token）`，未看够 15 秒是 `等待观看进度（Ns/15s）`，失败则是 `检测失败（冷却后自动重试）: name: message`）、中继（宿主报错 / 端口断开 / 外部信号中止）。

常见现象先看哪里：

| 现象 | 先看哪里 |
| --- | --- |
| 「请求发不出去」 | 系统代理——本地代理工具需放行该端点域名或配直连规则 |
| 「扩展后台未响应，请重载扩展」 | 构建更新后没重载扩展：扩展管理页重载扩展，再刷新页面 |
| 视频没有广告标记 | 控制台看 `字幕=N行`：0 行说明字幕没取到（未登录 / 无字幕轨）；行数正常但 `广告段=0`，查诊断控制台里的失败记录 |
| 有报错但诊断控制台是空的 | 那条报错不是 AI 链路发出的；到页面控制台找 `[bili-helper]` 前缀日志 |

### 转发服务端（可选部署）

仓库自带一份服务端参考实现 `server/`，让「我有自己的服务器」开箱可用：

```bash
pnpm server:build                      # → server/dist/server.mjs（单文件、零运行时依赖）
AI_API_URL=… AI_MODEL=… AI_SERVER_TOKEN=… node server/dist/server.mjs
```

可选变量还有一组：`AI_API_KEY`、`AI_EMBED_BASE_URL` / `AI_EMBED_MODEL` / `AI_EMBED_API_KEY`（向量端点拆分）、`AI_SERVER_HOST`、`AI_SERVER_ORIGIN`（CORS）、`AI_SERVER_STORAGE_FILE`（用户词库与向量缓存的落盘位置）。

它**直接复用 `modules/ai` 里的同一套混合检索 RAG 与提示词**（不是另写一份），因此两种模式的识别口径一致；相比浏览器直连，它不受本机网络与代理环境影响、Key 不出服务器、向量缓存集中一份。契约、环境变量、反代与公网暴露注意事项见 [server/README.md](server/README.md)。

## 📄 安装与使用

1. 安装依赖：`pnpm install`；
2. 源码构建：`pnpm dev`（开发构建，`.output/chrome-mv3`）或 `pnpm build`（生产构建；`pnpm zip` 额外打包 zip）；
3. 打开浏览器的扩展管理页，开启「开发者模式」；
4. 选择「加载已解压的扩展程序」，指向 `.output/chrome-mv3` 目录；
5. 打开 bilibili.com，在扩展设置页按需开启功能、配置 AI 端点。

补充：`pnpm dev` 会在开发模式下热更新产物，改完代码重载扩展即可；`pnpm test` 跑单元测试；`pnpm server:build` + `pnpm server:start` 构建并启动可选的转发服务端（见 [server/README.md](server/README.md)）。

> **每次更新产物后都要在扩展管理页重载扩展，再刷新 B 站页面**。扩展的后台 service worker 在重载前会一直跑旧注册：只刷新页面会让「新内容脚本 + 旧后台」对不上，表现为 AI 掉线、报「扩展后台未响应」。

### 装好之后建议这样过一遍

单元测试覆盖了逻辑与契约，但 B 站真实 DOM、SPA 换视频、全屏重挂载这些只能在浏览器里验：

1. **端点**：设置页填对话端点 → 卡片里点「测试连接」应当绿灯；故意把 API Key 改错一位，应当红灯并直指 Key。红灯报「请求没发出去」时先查系统代理（本地代理工具需放行该端点域名）。
2. **去广告**：打开「AI 去广告」总开关，找一个明显恰饭的视频 → 实际看够 15 秒后开始检测（没看够时控制台会打 `等待观看进度`，秒退不花 token）、播放器顶部出现提示条、**3 秒倒计时后自动跳过**（什么都不点也会跳）、进度条上出现广告标记；点「这段想看」应当留在原地。
3. **省 token 链路**：同一个视频刷新页面再进 → 控制台应打 `检测缓存命中 …（0 token）`；设置页诊断控制台「去广告开销」应逐条列出路径与 token 用量；弹幕刷「恰饭」明显的视频有机会走 `双源强一致(免LLM)`（0 对话调用）。
4. **进度条标记**：鼠标移入播放器让控制层浮现 → 标记应正好落在进度条上；等控制层自动淡出 → 标记必须跟着消失（不该悬在原地）；鼠标再回来 → 标记复现。
4. **面板**：右侧「总结」生成正文与分段时间线，点分段跳播、广告段带标签；「提问」流式输出、溯源 chip 点击跳播；折叠再展开，已生成的内容应当还在。
5. **换视频**：从当前视频点推荐位跳到另一个视频（不刷新页面）→ 面板与广告标记必须整体复位，旧视频的广告段不能出现在新视频时间线上。
6. **补录词条**：设置页「广告词库」补一个该视频里的品牌词（或用面板底部「漏检补录」勾选当前时间点附近的候选词）→ 重新打开那个视频 → 这一段应当被召回；设置页里该词的「命中」计数应当增加。
7. **降级**：把「高级」里的向量端点填成一个坏地址 → 应当看到向量端点故障的一次性提示，但识别仍然出结果（退纯词表）；再把对话端点也填坏 → 应看到「极速匹配」的一次性提示，识别仍出结果（纯检索定界，只打标记、不自动跳），不应无限重试或卡死。
8. **排障入口**：做几件会失败的操作（例如填错 Key 后点测试连接、拉一次模型列表）→ 设置页「诊断控制台」应当逐条列出失败时间、功能、原因与原始回复摘录；清空后列表归零。
9. **服务器模式**（可选）：`pnpm server:build && pnpm server:start` 起服务，设置页打开「我有自己的服务器」填地址与 token → 测试连接绿灯 → 去广告/总结/提问照常；此时词库卡应当提示补录只在浏览器直连时生效。
